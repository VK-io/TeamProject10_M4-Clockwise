# Clockwise: Updated Business Model Canvas (M4)

> **[CHANGED]** marks blocks that moved because of M3/M4 findings. "T1"–"T5" refer to the user testing sessions in `user_testing_sessions.md`.

| Block | M4 content | Changed? Why |
|---|---|---|
| **Customer Segments** **[CHANGED]** | **Paying customer:** a university student-success, advising or IT office (FGCU first), licensing for all students. **Primary users:** undergraduates juggling many courses or side commitments (jobs, startups) who need help deciding what to work on next. **Secondary:** advisors tracking at-risk students; other Canvas schools. | M2 → individual students as the customers. Changed because the M3 cost model needs ≈4,400 paying users to break even. M4 testing sharpened the user: the tester already "on top of" his work would not use it (T5); testers balancing coursework with a business or validation project valued it most (T1, T2). |
| **Value Propositions** **[CHANGED]** | Students: "Know exactly what's due, in the right order, and when to do it": accurate deadlines from your own Canvas, a ranked weekly plan, and calendar export; alerts only when something actually changes. Institution: fewer missed deadlines and better retention on its existing Canvas. Reliability: every alert is checked against Canvas data before it is sent. | M2 → "get alerted when a deadline moves." Changed because 4/5 testers asked for planning (calendar, time blocks, ranking, time estimates) and nobody asked for more alerts. Accuracy is now explicit because 3/5 testers saw wrong times before the M4 fix. |
| **Channels** **[CHANGED]** | Pilot through FGCU IT or Student Success; in-Canvas placement (LTI) or campus app listing; orientation and advisor referrals; student clubs (entrepreneurship, software). Mobile web app, no separate notification app required. | M2 → direct student download and word of mouth. Changed to match the institutional buyer, and because two testers (T4, T5) would not install a third-party alert app on top of Canvas notifications. |
| **Customer Relationships** **[CHANGED]** | Self-service: connect once, then ask in plain language and get a plan. Alerts are opt-in and customizable, silent unless something changes. Institution gets a pilot contact and a termly usage report. Open-source code as a trust signal. | M2 → passive alerts. Changed because testers want an advisor they talk to (T1, T4), customizable notifications (T4), and T4 said visible code made it "more trustworthy and secure." |
| **Revenue Streams** **[CHANGED]** | **Campus license ≈ $1 per student per year.** FGCU (≈16,000 students) brings ≈$1,333/mo, covering the 10,000-user cost ($1,104/mo). Pilot funded by student-success or grant money. | M2 → freemium, Premium $19.99/yr. Changed because freemium doesn't break even at realistic scale (M3), and T1 independently suggested the school adopt it. |
| **Key Resources** | Canvas API access (institutional developer key in production), the LLM (NRP gpt-oss, hosted gpt-oss fallback), the two-agent code, cloud database, the evaluation suite + critic agent, team time. | Added the evaluation suite: it is how we prove reliability to an institutional buyer. |
| **Key Activities** **[CHANGED]** | Polling and diffing Canvas; building planning features (ranking, time estimates, calendar export); keeping guardrails tuned; running the eval suite on every change, including real-world date checks; performance work; user testing; institutional sales. | Added planning features and performance work from M4 testing; added real-world date checks because the timezone bug passed the eval suite. |
| **Key Partners** | FGCU IT / Instructure Canvas (API, LTI), NRP Nautilus (free academic inference), a hosted model provider as fallback, calendar providers (Outlook/Microsoft 365), Student Success / Advising (pilot sponsor). | Added calendar providers (T4 asked for Outlook export). ntfy.sh is now optional, not core. |
| **Cost Structure** | Mostly labor: maintenance $200 / $400 / $800 per month at 100 / 1k / 10k users. Hosting $6 / $24 / $108; DB $0 / $15 / $75; inference $1 / $12 / $121 on hosted gpt-oss ($0 on NRP). Totals $207 / $451 / $1,104 per month. | Unchanged from M3. Planning answers add chat calls, but the template fallbacks add none and the critic runs only in evaluation. |
